# «Цифры команды»

Внутренний Telegram-бот данных в `lib/databot/`: отчёты, справочник и доступы. Задачи команды теперь обрабатывает «Пятница» (`lib/team/`), сохраняя их в таблицах `databot_assigned_tasks`. Источник задач — личный чат владельца с «Пятницей».

## Запуск

Для отдельного бота данных нужны `037_databot.sql`, серверный доступ Supabase и переменные `DATABOT_TOKEN`, `DATABOT_WEBHOOK_SECRET`, `DATABOT_OWNER_IDS`, `NEXT_PUBLIC_APP_URL`. Задачам «Пятницы» дополнительно нужны `040_databot_assigned_tasks.sql`, `043_databot_assigned_lifecycle.sql`, `044_databot_assigned_multi_recipient.sql`, `TEAM_BOT_TOKEN` и `TEAM_WEBHOOK_SECRET`. При общем токене webhook регистрирует только «Пятница».

### Задачи команды в «Пятнице»: `/assign`

Командный чат и топики не нужны.

**Раздать.** Владелец отправляет боту в личку список, первой строкой `/assign`, либо открывает `/tasks` и присылает список следующим сообщением. Одна строка — одно дело в формате «что делать / дедлайн / @ник + @ник»:

```text
/assign
Подготовить макет / пт 18:00 / @alice + @bob
Проверить текст / 03.10 / @bob
```

Каждому указанному исполнителю создаётся отдельная задача с собственным статусом. Бот понимает сроки «пт», «пятница», «завтра 12:00», «послезавтра», «03.10», «03.10.2027», «18:00» (то есть сегодня). Без времени срок — конец дня, 23:59 МСК. «10.01» в декабре значит январь следующего года. Прошедший срок, несуществующая дата или неизвестный ник отменяют сохранение всего списка, и бот называет строку с ошибкой. В ответ владелец получает разобранный список с номерами задач и сроками. Старые форматы с `--` и «@ник — задача до срока» также поддерживаются.

Каждый ник должен точно соответствовать одному действующему участнику `team_members`. Перед обработкой задач бот синхронизирует состав с `databot_members`. Повторная обработка того же сообщения не создаёт дублей. Исправленный список присылайте новым сообщением.

**Исполнитель** получает задачу в личку с кнопками и видит ники сокомандников, которым назначена та же строка списка. Те же карточки есть в «Моих задачах» (кнопка меню, `/tasks`, `/assigned`):

| Статус | Кнопки |
| --- | --- |
| 🆕 новая | «Взял в работу», «Сделано», «Не смогу» |
| 🔄 в работе | «Сделано», «Не смогу» |
| ✅ сделано | «Вернуть в работу» |
| ↩️ не сможет | «Всё-таки возьму» |
| ✖️ отменена | — |

Нажимать может только сам исполнитель, проверка идёт по Telegram ID. Повторное нажатие ничего не меняет. Владелец, поставивший задачу, получает сообщение на «Сделано», «Не смогу» и возврат в работу. «Взял в работу» видно в обзоре, отдельным сообщением о нём бот не пишет.

**Владелец:**

- `/assign_status` — кто что делает: по людям, сначала просроченное, затем по сроку; выполненные и другие закрытые задачи показаны отдельными строками;
- `/assign_edit ID новый текст [до срок]` — поправить текст и/или срок;
- `/assign_due ID пт 18:00` — сменить срок, `/assign_due ID нет` — снять его;
- `/assign_cancel ID` — отменить задачу;
- `/assign_retry ID` — повторить доставку после того, как человек открыл бота.

О правке, новом сроке и отмене исполнитель узнаёт сразу. Его исходное сообщение с задачей бот тоже обновляет. Закрытую задачу править нельзя, назначить заново — новым `/assign`.

**Напоминания** рассылает тот же 15-минутный тикер из `instrumentation.ts`:

- за сутки до срока, если задачу поставили больше чем за сутки; за три часа, если меньше чем за сутки, но больше чем за 6 часов; на совсем короткие задачи напоминаний нет;
- когда срок прошёл, а задача не закрыта, — одно сообщение исполнителю и одно владельцу;
- с 22:00 до 09:00 МСК бот молчит. Напоминание к сроку «до пятницы» уходит в 09:00 пятницы.

Повторов не будет: отметки `reminded_at` и `overdue_notified_at` ставятся в базе до отправки. Если поменять срок, отметки сбрасываются, и бот напомнит о новом сроке заново.

Если человек ещё не открыл бота или заблокировал его, задача остаётся в списке с пометкой 📭. При неопределённом сетевом результате повторная доставка блокируется до ручной проверки лички получателя, чтобы не появился дубль. Содержимое задач в общий аудит не пишется.

Production webhook `/api/telegram/databot-webhook` регистрируется при старте приложения. Next.js читает ключи из `.env` при локальном запуске приложения. Для разработки — `npm run databot:dev` с отдельным тестовым токеном в `.env`: этот скрипт сначала читает `.env`, затем дополняет отсутствующие переменные из `.env.local`; уже заданные переменные процесса имеют приоритет. Скрипт отказывается снимать обнаруженный production-webhook. Реальные токены не нужны для unit-тестов.

В репозитории нет настроенной команды применения миграций. Администратор проверяет, что `037_databot.sql`, `040_databot_assigned_tasks.sql`, `043_databot_assigned_lifecycle.sql` и `044_databot_assigned_multi_recipient.sql` применены в Supabase, затем настраивает переменные окружения и перезапускает приложение.

## Подключённые разделы

| Команда | Раздел | Доступ |
| --- | --- | --- |
| `/runs` | Забеги, участники, план явки и динамика | По матрице доступа; персональные списки доступны Совету и Ивентам в ограниченном окне |
| `/kb` | Справочник | Статьи своей зоны; Совет читает все и редактирует |
| `/team` | Команда и использование бота | Совет; управление участниками — владелец |
| `/pro` | Про и оплаты | Совет |
| `/product` | Продукт | Совет |
| `/tasks` | Мои задачи из `/assign` со статусами и кнопками | Каждый действующий участник |

`/social` пока отвечает, что раздел ещё собирается. Текстовые вопросы сейчас ищут статьи справочника; произвольный запрос к отчётам через LLM не подключён.

## Про и оплаты, Продукт

По умолчанию показывается текущий месяц. Кнопки переключают период: **7 дней**, **прошлая неделя**, **этот месяц**, **30 дней**. Границы считаются по Москве; текущие периоды заканчиваются в момент запроса. Прошлая неделя — законченные понедельник–воскресенье. Длинные списки разбиты на страницы с кнопкой «Ещё»; при каждом запросе данные читаются заново.

Оба раздела используют существующие RPC `databot_pro` и `databot_product` из миграции `037`; новых таблиц и миграций для экранов не требуется. Ошибка БД отображается как ошибка, а не как нулевой отчёт. Смена периода записывается в аудит. Права проверяются и для команд, и для нажатий кнопок; СММ и Ивенты не получают эти данные.

### `/pro`

- Количество PRO сейчас с разделением на оплату, промо и ручную выдачу.
- Количество и сумма успешных оплат за период, разбивка по планам.
- Погашения промокодов за период и разбивка по кодам.
- Сколько пользователей, погасивших промо в периоде, оплатили позже — по всем имеющимся последующим оплатам, не только внутри выбранного периода.
- Количество пользователей PRO с активной подпиской, истекающей в ближайшие 7 дней.

PRO сейчас и ближайшее истечение подписок — текущий снимок, они не меняются при выборе исторического периода. Суммы — в рублях, копейки сохраняются. Аккаунты команды исключает SQL.

### `/product`

- Регистрации за период; из этих пользователей — прошедшие онбординг и имеющие активную привязку Telegram по текущему состоянию.
- Активные пользователи за 7 дней до конца периода — все пользователи, а не только новые регистрации.
- Спринты, начатые и закрытые за период; отдельно — активные сейчас.
- Отправленные утренние сообщения и переходы по ним.
- Регистрации по каналу последнего касания.
- Возврат после пропуска: пока **«нет данных»**, потому что RPC возвращает `nsm=null`.

Текущая SQL-функция считает утренние сообщения по полным московским календарным дням: сегодняшний неполный день не входит. Экран прямо подписывает это ограничение. Аккаунты команды исключены из расчётов.

## Код и проверки

- `sections/summaries.ts` — обработчики двух отчётов, подписи метрик и страницы.
- `data/pro.ts`, `data/product.ts` — чтение и валидация RPC.
- `intent.ts` — разбор команд и кнопок периода/страницы.
- `access.ts` — единая матрица доступа.
- `sections.ts`, `handlers.ts` — включение разделов и регистрация обработчиков.

```sh
npm test -- lib/databot/sections/summaries.test.ts lib/databot/pipeline.test.ts lib/databot/access.test.ts lib/databot/privacy.test.ts
```

Тесты проверяют московские границы периода, права до чтения данных, ошибку БД, аудит, экранирование HTML, различие нуля и отсутствия данных, сохранность длинных списков и лимиты Telegram.
