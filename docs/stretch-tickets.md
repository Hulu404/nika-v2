# Билеты /stretch

Один заказ содержит от 1 до 16 билетов на одно занятие. Сервер умножает цену
из `lib/clubs/sessions.ts` на количество, Telegram выставляет один счёт.
Чек содержит количество билетов и цену одного билета. Лимит зала учитывает
сумму `quantity` оплаченных заказов с `counts_seat = true`.

Виджет получает точный остаток `available` из `/api/club-signup` и ограничивает
кнопки, ручной ввод и отправку меньшим из значений 16 и остатка. Он обновляет
остаток при открытии страницы, возвращении на вкладку и каждые 30 секунд.
Если выбранное количество стало недоступно, пользователь должен уменьшить
его. При нулевом остатке выбор количества скрыт и доступен лист ожидания;
при ошибке получения остатка покупка блокируется до успешного обновления.
Ответ 409 при оформлении также обновляет максимум в виджете. Проверка в боте
перед списанием дополнительно учитывает активные резервы других платежей.

В режиме «В подарок» покупатель указывает свои контакты и имя получателя.
Анкета о пилатесе и инвентаре не требуется. Все билеты заказа предназначены
получателю и его компании. После оплаты покупателю приходит отдельное
сообщение без цены с количеством, датой, адресом и номером заказа. Покупатель
сам пересылает его получателю; автоматической отправки получателю нет.
Повторный вход в бот по ссылке заказа повторно показывает подарок.

В обычном заказе анкета относится к покупателю; пожелания остальных гостей
уточняются на месте. Подтверждение сообщает количество мест и имя покупателя
для входа. Подарочное сообщение предъявляют на входе; номер заказа соответствует
`club_signups.id`. Автоматического погашения билетов/QR-проверки нет.

Каждая новая покупка получает случайный `request_token` (32 hex), который
сохраняется как `confirm_token`. Сетевой повтор с тем же ключом возвращает
тот же неизменный заказ. Новый заказ можно оформить с тем же Telegram.
Старая форма без ключа возвращает предыдущую заявку по Telegram.

Перед списанием `reserve_club_tickets` сериализует проверки на занятие через
транзакционную advisory-блокировку. Она учитывает оплаченные места и резервы
одобренных платежей; резерв действует 15 минут. Повторная попытка оплаты
того же заказа во время резерва отклоняется. Неоплаченные формы сами по себе
места не занимают. Успешный платёж подтверждается только по уведомлению Telegram.

## Выкладка

1. Применить `supabase/migrations/068_club_ticket_orders.sql` после 067.
   Старые заявки получат `quantity = 1`, `is_gift = false`.
2. Выкатить API, лендинг и Telegram-обработчик вместе. Старый бот не умеет
   учитывать несколько билетов в заказе и не должен обслуживать новые заказы.
3. Проверить в тестовом окружении платёж за несколько билетов, подарок,
   повтор уведомления и одновременные попытки выкупить последние места.

Миграция подготовлена в репозитории; применение к рабочей БД и реальные
платежи не входят в локальные автоматические проверки.

Проверки: `npm test -- app/api/club-signup/route.test.ts lib/clubs/seats.test.ts lib/telegram/club-signup.test.ts lib/telegram/club-signup-handlers.test.ts`.
