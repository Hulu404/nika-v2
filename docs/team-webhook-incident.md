# @assistant_nikabot: команды и кнопки не доставлялись

Проверка 2 ноября 2026 года подтвердила, что `TEAM_BOT_TOKEN` относится к
`@assistant_nikabot`. Telegram `getWebhookInfo` показывал правильный адрес
`https://www.mynika.online/api/telegram/team-webhook`, очередь из 4 событий и
`Wrong response from the webhook: 401 Unauthorized`.

Webhook-роут возвращает 401 при отсутствующем/неверном
`x-telegram-bot-api-secret-token`. Безопасная проба с текущим
`TEAM_WEBHOOK_SECRET` и намеренно невалидным JSON получила `400 Bad Request`:
сервер принял секрет и дошёл до разбора тела, не запуская обработчики.
После `setWebhook` с этим секретом и `drop_pending_updates: false` очередь
стала равна 0, ошибка исчезла. Это подтверждает рассогласование регистрации
webhook с серверным секретом. Кто и когда изменил регистрацию, не установлено.

Напоминания используют исходящие запросы Telegram API и не проходят через
входящий webhook, поэтому продолжали приходить. Разгрузка очереди подтверждает
доставку HTTP-запросов; отдельно фактические ответы в чате пользователя не проверялись.

## Исправления

- На рабочем боте переустановлен webhook с проверенным секретом без сброса очереди.
- В код добавлена проверка каждые 15 минут: восстановление адреса, подписки
  на команды/кнопки и секрета при 401 с очередью. Ошибки другой природы логируются.
- Проверка работает без обновления меню и чтения команды из БД; пересекающиеся
  проверки в одном процессе исключены.
- Ошибка синхронизации меню больше не выдаётся за неуспешную регистрацию webhook.
- `npm run team:dev` проверяет production-webhook до запуска polling и отказывается
  его отключать. Сбой проверки тоже запрещает старт. При отсутствии webhook
  определить, является ли токен боевым, по этой проверке нельзя: для разработки
  по-прежнему нужен отдельный тестовый бот.

Изменения кода вступают в силу после деплоя. Исправление регистрации в Telegram
выполнено отдельно и уже действует.

Проверки: 66 тестов (регистрация webhook, защита polling, меню, задачи,
переключение проектов, фоновая обработка), TypeScript `--noEmit` и ESLint
изменённых файлов прошли. Для проверки восстановлена отсутствовавшая локально
зависимость `undici`; `package.json` и `package-lock.json` не изменены.

## Повторная диагностика

Проверить `getMe` и `getWebhookInfo` через Bot API, не выводя токен. При 401
сверить `TEAM_WEBHOOK_SECRET` с runtime-настройкой сервера. Переустанавливать
webhook только на проверенный адрес с проверенным секретом, сохраняя очередь.
Не запускать polling для проверки production-бота и не отключать проверку секрета.

Семантика параметров и полей: [Telegram Bot API — setWebhook и getWebhookInfo](https://core.telegram.org/bots/api#setwebhook).
